## Мета

Ознайомитися з базовими методами навчання без учителя та обробки текстових
даних: зниженням розмірності, візуалізацією і кластеризацією даних, а також
побудовою базового workflow класифікації текстів з використанням бібліотеки
scikit-learn.

## Завдання

1. **Зниження розмірності та візуалізація** — PCA на датасеті з лабораторної
   № 1, класифікація «до» і «після» PCA; t-SNE у 2D.
2. **Кластерний аналіз** — K-Means без міток класів, вибір кількості кластерів
   (Elbow, Silhouette), візуалізація у 2D, порівняння кластерів із класами.
3. **Класифікація текстів** — передобробка, WordCloud характерних слів для
   кожного класу, TF-IDF, класифікатор і метрики.

## Датасети

- [Ethereum Fraud Detection](https://www.kaggle.com/datasets/vagifa/ethereum-frauddetection-dataset) —
  той самий, що в лабораторній № 1 (частини 1–2).
- [CVE & CWE Dataset (1999–2025)](https://www.kaggle.com/datasets/stanislavvinokur/cve-and-cwe-dataset-1999-2025) —
  описи вразливостей із NVD, класи критичності за CVSS v3: MEDIUM, HIGH,
  CRITICAL (частина 3, по 15 000 описів на клас).

## Основні результати

- **PCA** стискає ознаки лише вдвічі: 32 компоненти з 60 для 99 % дисперсії.
  З ними SVM дає F1 = 0.980 проти 0.981 без PCA, але навчання не
  пришвидшується. Різке падіння якості на кількох компонентах — здебільшого
  наслідок гіперпараметрів, підібраних для повного простору.
- **t-SNE** добре розділяє класи й сам виокремлює групу з 829 акаунтів без
  ERC20-даних — артефакт датасета, знайдений у лабораторній № 1.
- **K-Means** на стандартизованих ознаках вироджується (відокремлює два
  викиди), попри silhouette = 0.98. Після логарифмування важкохвостих ознак
  кластери відповідають рівню активності акаунта, а не класу (ARI = −0.07). При
  більшому k з'являються підгрупи з часткою шахраїв від 0.7 % до 65 %.
- **Класифікація CVE:** Linear SVM на TF-IDF дає F1-macro = 0.70 при базовій
  лінії 0.33; 83 % помилок — між сусідніми рівнями критичності. Характерні
  слова класів відтворюють логіку CVSS: XSS → MEDIUM, локальне підвищення
  привілеїв → HIGH, віддалене виконання коду без автентифікації → CRITICAL.
- Перед навчанням на CVE прибрано три витоки мітки: змішування версій CVSS
  (у v2 немає рівня CRITICAL), описи, що цитують власну оцінку CVSS, та оцінки
  VulDB у тексті («classified as critical»).
